# Design Principles

1. Operator truth over spectacle. Every visual state maps to real telemetry, policy, event, or proof.
2. Firmware clarity. System state must be legible under stress, degraded networking, and partial failure.
3. Hotkey first. Every critical action has a deterministic keyboard path.
4. Progressive disclosure. Primary cockpit stays sparse; detail is one interaction away.
5. Bounded authority. UI never implies permission the runtime does not possess.
6. Local survival. ODIN remains useful offline with queue, journal, recovery, and cached topology.
7. Closed loop. Command -> route -> execute -> verify -> prove -> display.
8. No fake AI theater. Reasoning is summarized through observable orchestration events, never fabricated inner thought.
9. Cross-device consistency. TUI, web command center, and future surfaces share the same information architecture and event model.
10. Cinematic engineering is generated by real system motion.
