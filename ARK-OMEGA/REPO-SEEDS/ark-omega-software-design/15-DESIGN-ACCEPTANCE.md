# Design Acceptance Criteria

The software design is accepted when an implementer can build the ODIN TUI and web command center without inventing architecture.

Acceptance proof requires:
- seven-domain IA
- deterministic hotkey map
- peer/context switching semantics
- normalized component contracts
- complete mission state machine
- complete degraded/recovery model
- event-derived observability semantics
- security/authority presentation rules
- responsive/accessibility rules
- ADRs for cockpit role, cinematic truth, and VISHVARUPA succession
- implementation handoff gates
